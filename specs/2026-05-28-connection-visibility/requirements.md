# Requirements — Connection Visibility

Phase 4 makes the pipeline transparent: the user sees not just the quote but the chain that produced it. The app turns weather into a natural-language description, embeds it, and finds the nearest literary passage — but that chain is currently invisible. Without seeing the weather prose that was used as the search query, or how closely the quote matched, the selection feels arbitrary. This phase exposes those internals so the moment of recognition becomes legible.

## In scope

- **Weather prose in API response** — add `weatherProse` field (the `ToNaturalLanguage()` output) to the JSON returned by `GET /api/quote`
- **Similarity score visible in UI** — `score` is already in the response; display it as a readable percentage or label (e.g. "87% match") next to the attribution
- **Common word highlighting** — highlight words in the quote text that also appear in the weather prose; simple case-insensitive intersection, no ML
- **Debug toggles in UI** — three independent on/off switches (prose, score, highlights) so the user can turn each piece of debug info on or off; off by default so the default experience is uncluttered

## Out of scope / deferred

- Explanation generated by an LLM ("why this quote?")
- Semantic keyword extraction (TF-IDF, attention maps, etc.)
- Persisting toggle state across sessions (localStorage)

## Decisions

- **Collapsible prose block** — the weather prose appears in a `<details>`/`<summary>` element (or Alpine toggle) below the card; collapsed by default so it doesn't compete with the quote on first render.
- **Client-side highlighting** — word intersection computed in Alpine.js; no backend changes needed for highlights. The prose is already sent from the API.
- **Score as percentage** — cosine similarity score (0–1) displayed as `Math.round(score * 100)%`. Avoids raw decimals that mean nothing to a non-technical reader.
- **Toggles are debug controls, not primary UI** — styled visually lighter than the main card; grouped in a small "Show:" row beneath the "Try another" button.

## Constraints

- Frontend stays Alpine.js + plain HTML/CSS, no build step
- API contract change is additive only (`weatherProse` is a new field; existing fields unchanged)
- All 89 automated tests must continue to pass; the new field should be covered by at least one E2E assertion
